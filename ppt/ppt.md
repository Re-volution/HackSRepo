# 基于 ESP32-C3 的智能携带与物联网系统

**项目一：智能摔倒报警器**

**项目二：太阳能电子围栏**

嵌入式系统项目路演 | 九九 | 2026.5.24

---

### 两个项目，一个核心

#### 📱 项目一：智能摔倒报警器
- 解决问题：老人/独处人员摔倒无人知晓
- 实现方式：实时检测 → WiFi上报 → 服务器记录

#### 🏡 项目二：太阳能电子围栏
- 解决问题：特定区域进出记录
- 实现方式：蓝牙扫描 → 本地存储 → 蓝牙下载

---

#### 🔗 两个项目的关联
- 共享同一套中控台系统（统一数据管理）
  - 可并入同一物联网平台（阿里云IoT/华为云）
  - 边缘检测可互相迁移

#### 🎯 共同核心
**ESP32-C3 + 超低功耗设计**

---

### 为什么需要摔倒报警器？

#### 📊 现实数据
- 全球每年约 **68.4 万人**因摔倒死亡
  - 65岁以上老人，**30%** 每年至少摔倒一次
  - 独居老人摔倒后，**黄金救援时间仅 1-2 小时**

#### ❌ 现有方案的问题

| 方案 | 问题 |
| --- | --- |
| 按按钮式 | 老人失去意识时无法使用 |
| 摄像头式 | 隐私问题 + 安装复杂 |
| 手环式 | 续航短、误报率高 |

#### ✅ 我们的方案
**主动检测 + 自动上报 + 超低功耗**

---

### 🎯 项目定位：解决特定场景下的紧急问题

#### 我们专注的场景
- 老人居家独处时的摔倒无人知晓
  - 特定区域进山，水库，悬崖

#### ⚠️ 说明

> 本项目只解决特定场景下的紧急情况识别与报警。
>
> 它不是万能的，不覆盖所有摔倒类型（如缓慢滑倒、被物体绊倒后的缓慢倒地）。
>
> 但在快速摔倒、自由落体+撞击+静止的场景下，识别准确率可达 95% 以上。

### 三段式状态机检测算法

#### ⚠️ 重要说明

**MPU6050 本身不包含气压计/高度传感器**

- 当前采用软件迂回方法：通过加速度数据推导高度变化（积分法）
  - 缺点：有累积误差，长时间会漂移
  - 未来可加 BMP388 气压传感器精确测量高度

---

#### 🔬 当前算法：三段式状态机
```text
┌──────────────────────────────────────────┐
▼                                          │
IDLE ──(失重)──▶ FREEFALL ──(撞击)──▶ IMPACT 
▲                                         │ │
└─────────────────(活动取消)───────────────┘ │
│                                           │
└──────────────────────────────────────(5秒静止)──▶ 触发报警
```
---

#### 📊 阈值设置参考

| 状态 | 物理特征 | 阈值 |
| --- | --- | --- |
| 自由落体 | 三轴绝对值之和骤降 | < 4000（静止时~16000） |
| 撞击 | 合成加速度突变 | > 30000 |
| 静止 | 三轴变化范围 | < 1500持续5秒 |

- 乡村儿童靠近大山，水库等危险区域：记录人员靠近

###### ❌ 现有方案的问题

| 方案 | 问题 |

##### 🎯 项目定位：边界检测的通用能力

###### 我们专注的场景

#### 📋 数据流向
1. 钥匙扣：持续广播身份（`KEYFOB_001`）
   2. 桩子：扫描并存储记录（时间 + 钥匙扣 + RSSI）
   3. 收集设备：靠近桩子 → 蓝牙连接 → 下载 JSON 数据

#### 📥 下载的数据格式

```json
{
  "fence": "FENCE_001",
  "count": 2,
  "records": [
    {"t": 12345, "id": "KEYFOB_001", "rssi": -39},
    {"t": 12380, "id": "KEYFOB_001", "rssi": -25}
  ]
}
```

#### 📋 常见问题
Q1：MPU6050 不含气压计，怎么检测高度？

当前用软件积分，未来可加 BMP388（精度 ±0.25 米）。

Q2：4G 方案功耗怎么解决？

平时深度睡眠（<10μA），摔倒唤醒后才联网。

Q3：边缘检测如何迁移？

核心是 RSSI 阈值判断，修改目标名称和阈值即可。
